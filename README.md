# stop-loop — Claude Code 플러그인

카드 한 장을 열세 단계(분석 → 범위 검증 → 질문·답변 → 설계 → 설계 검증 → 시험 먼저 구현 → 품질 확인 → 검토 → 인계 → 회고)로
돌리는 워크플로우다. 검토 단계는 기본으로 꺼져 있고 설정 `reviewPolicy` 로 켠다. 단계마다 새 세션이 앞 단계의 산출물만 보고 일하고, 검증 단계는 만든 쪽과 다른 에이전트가 맡는다.

## 미리 필요한 것

| 무엇 | 확인 | 비고 |
|---|---|---|
| Claude Code | `ls ~/.local/bin/claude` | 러너가 이 경로를 직접 부른다 |
| python3 | `python3 --version` | 표준 라이브러리만 쓴다 |
| git 2.44 이상 | `git --version` | 카드마다 워크트리를 연다 |
| gh | `gh auth status` | 인계를 PR 로 할 때만 |

## 설치

```bash
claude plugin marketplace add dawn-island/stop-loop
claude plugin install stop-loop@stop-loop
```

판을 올릴 때는 `claude plugin update stop-loop@stop-loop`. 실행 도중 판이 바뀌면 러너가 다음 단계 앞에서 멈추고,
`--resume` 으로 이어받는다.

## 프로젝트에 세우기

프로젝트 뿌리에서 Claude Code 를 열고:

```
/stop-loop:setup
```

만들거나 고치는 것 — 커밋은 하지 않는다:

- `CLAUDE.md` — 없으면 틀로 만든다. 있으면 표준 구간만 바꾼다. `<…>` 자리표시(시험 명령, 실행하지 않을 명령, 신원 등)는 직접 채운다.
- `stop-loop.config.json` — **`checks` 를 이 프로젝트의 시험 명령으로 고친다.** 비워 두면 시험 없이 구현 단계를 통과한다.
- `docs/backlog/_템플릿.md` — 카드 틀.
- `.claude/settings.json` — 이 플러그인 선언.

GitHub 계정이 여럿이면 설정에 `"githubAccount": "<계정>"` 을 넣는다. 러너가 그 계정의 토큰만 쓰고, 올리기 전에 로그인
계정이 다르면 멈춘다.

## 쓰기

계획이 여러 카드로 나뉘면 시나리오부터(1), 카드 한 장이면 카드부터(2) 한다.

1. **시나리오를 쓰고 승인한다 — 사람이 깊이 관여하는 자리는 여기다.** 프로젝트 뿌리에서:

   ```
   /stop-loop:scenario
   ```

   스킬이 `docs/plan/SC-<번호>.md` 초안과 요소 카드 초안(`상태: 아이디어`)을 함께 만들고, 승인 전 점검 결과를 보여 준다.
   됐다고 하면 시나리오의 `상태` 를 「확정」으로 바꾼다. 승인은 시나리오와 카드 초안을 함께 한다.
   그다음 배차를 띄운다:

   ```
   /stop-loop:dispatch
   ```

   배차가 승인을 판정해 앞선 카드가 없는 카드부터 대기로 올리고, 대기 카드를 집어 러너로 돌린다. 조건을 채운 PR 은 러너가 병합하고,
   병합되면 다음 카드가 대기로 오른다. 더 돌 것이 없으면 배차는 스스로 끝난다. 마지막 카드가 끝나면 끝 보고(`docs/plan/끝보고-SC-<번호>.md`)가 생기고,
   사람이 그것을 보고 시나리오 상태를 「완료」로 바꿔 완료를 선언한다.
   승인한 뒤 고칠 때는 상태를 「초안」으로 내렸다가 고친 다음 「확정」으로 다시 올린다.
2. **카드 한 장만 돌릴 때** — `docs/backlog/<이름>.md` 에 카드를 쓰고(머리말 `상태: 아이디어`, 「사람이 하면 몇 분」과 최소 범위),
   **사람이** `상태: 대기` 로 올린 뒤 `/stop-loop:dispatch` 또는 `/stop-loop:loop <카드 이름>` 으로 돌린다.
   시나리오에 묶이지 않은 카드는 사람만 대기로 올린다 — 러너도 회고도 올리지 않는다.

PR 본문 맨 위에 판단표와 「사람 결정 미결」이 있다. 자동 병합되지 않은 PR 은 사람이 보고 병합한다.

진행은 보드로 본다 — 사람이 할 일이 맨 위 「내가 할 일」에 모인다:

```
/stop-loop:board
```

배차와 보드는 그 기계의 목록 파일 `~/.stop-loop/projects.json` 에 등록된 프로젝트를 본다. `/stop-loop:setup` 이 등록한다.

## 워크플로우 개선을 알리기

회고 단계는 워크플로우에서 고칠 것을 「## 워크플로우 몫」(PR 본문 끝)에 적는다.
워크플로우 몫은 이 저장소의 이슈로 모은다. 러너가 PR 을 연 가지(`loop/<카드>`)에서, 프로젝트 뿌리에서:

```
/stop-loop:report
```

1. 먼저 아무것도 올리지 않고 「올릴 문장」을 보여 준다. 회사 정보 검사를 거친 문장이다.
   같은 이슈가 이미 있으면 「댓글을 단다 #번호」로 보여 준다.
2. 사람이 그 문장을 확인했을 때만 스킬이 올린다. 확인이 없으면 올리지 않는다.
3. 「올리지 않는다 — …」 줄은 회사 정보가 걸린 자리다. PR 본문의 그 칸을 고친 뒤 다시 부른다.

커밋은 하지 않는다. 카드 끝에 이슈 주소 한 줄이 더해지면 `git diff` 로 확인하고 커밋은 사람이 한다.
