## 작업 절차 — 모든 작업에 적용한다 (STOP-LOOP 1층 표준 v2)

단계마다 확인받지 않고 진행한다. 다만 **막히거나 사람의 결정이 필요하면
멈추고 물어본다.**

1. **설계** — 구현 전에 설계 문서를 먼저 쓴다.
   화면이 있는 작업이면 `loop-ux` 서브에이전트로 시안을 함께 낸다.
   시안은 HTML 로 `design/proposals/<이슈번호>-<화면키>.html` 에 쓴다.
   색·간격·글자크기는 `design/tokens.css` 의 변수만 쓰고 값을 직접 적지 않는다.
   새 컴포넌트를 만들기 전에 `design/components/` 를 먼저 읽는다.

2. **설계 검토** — `loop-verifier-design` 서브에이전트로 띄운다.
   **같은 대화에서 검토하지 않는다.** 검토자는 이슈 원문·설계 문서·시안만 보고
   작업 과정과 대화는 보지 않는다.
   major 이상 발견이 있으면 전건 수정 후 재검토한다. 통과할 때까지 반복한다.

3. **테스트 먼저** — 구현 전에 실패하는 테스트를 쓴다.

4. **구현** — 설계 문서대로 만든다. 설계에 없는 것을 더하지 않는다.
   필요해 보이면 이연 후보로 적고 넘어간다.

5. **품질 확인** — `loop-verifier-qa` 로 실제로 돌려본다.
   저장한 값을 다시 조회해 단언한다. 테스트가 통과하는 것과 동작하는 것은 다르다.

6. **검토** — `loop-verifier-review` 로 검토하고, Gap 이 95% 미만이면 재수행한다.
   이어서 `/ponytail-review` 로 과범위·오버스펙을 본다.
   발견은 한 줄로 적는다: 위치 · 뺄 것 · 대신할 것.

### 디자인 시스템 — 정본은 저장소다

`design/DESIGN.md`(원칙·브랜드)와 `design/tokens.css`(변수)가 진짜다.
claude.ai/design 은 올려 보는 거울이고, 둘이 다르면 **저장소가 맞다.**
클라우드에서 시각적으로 탐색하는 것은 자유이나, 저장소 파일에 반영해야 확정이다.
