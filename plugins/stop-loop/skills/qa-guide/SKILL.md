# qa-guide — 프로젝트 조작 안내서를 만든다

프로젝트 뿌리에서 부른다. 결과는 `docs/qa-guide.md` 한 장이다. 08 품질 확인(앱을 띄워 직접
조작해 보는 검증 단계)이 이 문서를 먼저 읽으므로, 여기 적힌 대로 사람 없이 앱을 띄우고
조작하고 끌 수 있어야 한다.

## 저장소 조사

사람에게 묻기 전에 저장소에서 먼저 찾는다. 찾은 곳을 안내서에 근거로 남긴다.

- 패키지 스크립트(`package.json` 의 scripts, `pyproject.toml`, `Cargo.toml` 등)와 `Makefile` — 기동·시험 명령
- `README` 와 `docs/` — 띄우는 법, 포트, 데이터 폴더, 환경 변수
- 기존 브라우저 시험 스펙(Playwright·Cypress 등) — 조작 순서와 준비 신호
- 컨테이너·설정 파일 — 데이터베이스와 마이그레이션·시드

## 사람에게 묻기

조사로 알 수 없는 것만 묻는다. 조사 대상이 하나도 없는 저장소면 기동·진단·증거 방법을
묻는다. 묻고도 채울 것이 없는 절에는 틀 규칙대로 「없음」을 적는다.

## 안내서 쓰기

`${CLAUDE_PLUGIN_ROOT}/workflows/stop-loop/templates/QA-guide.template.md` 를 읽고, 절 제목을
바꾸지 않은 채 조작 절 다섯(기동·진단·격리·증거·정리)을 채워 `docs/qa-guide.md` 에 쓴다.
「기동」 절의 「떴다」 기준은 프로세스가 응답하는 것이 아니라 쓸 수 있는 상태여야 하고,
빈 데이터 폴더에서 마이그레이션·시드까지 거쳐 띄우는 명령을 적는다.

## 한 번 돌리기

안내서를 넘기기 전에 적힌 그대로 한 번 돌려 본다.

1. 기동 — 안내서의 명령으로 띄우고 준비 신호를 기다린다.
2. 진단 — 읽기 전용 점검을 돌려 정상 출력인지 본다.
3. 기능 하나 — 앱의 기능 하나를 안내서대로 조작한다.
4. 증거 — 안내서가 정한 자리에 증거를 남긴다.
5. 정리 — 내가 띄운 것만 끈다.
6. 정리 뒤 — 정리한 다음에도 증거가 적힌 자리에 남아 있는지 확인한다.

실패하면 안내서를 고쳐 다시 돌린다. 실패한 시도마다 정리를 돌려 남은 프로세스를 없앤다.
실제 대상을 띄울 수 없어 다른 환경에서 증명했으면, 그 환경이 해 주고 실제 대상은 해 주지 않는
준비 단계를 목록으로 안내서에 남긴다. 한 번도 돌리지 않은 안내서에는 「초안」이라고 적는다.
