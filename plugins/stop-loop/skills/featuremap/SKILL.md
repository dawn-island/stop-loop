# featuremap — 기존 기능을 기능맵에 채운다

프로젝트 뿌리에서 부른다. 기능맵이 비어 있으면 카드 `기능:` 에 적을 ID 가 없어 기존 기능이
맵에 들어갈 길이 없다. 이 스킬은 영역 하나를 조사해 줄을 덧붙인다. 러너는 부르지 않는다.

## 범위

`/stop-loop:featuremap <폴더 경로 또는 시나리오 번호>` 로 부른다. 폴더 경로(예 `src/billing/`)나
시나리오 번호(예 `SC-003`) 하나가 범위다.

범위를 주지 않으면 무엇부터 할지 사람에게 묻는다. 저장소 전체를 한 번에 하지 않는다.

기능맵(`docs/기능맵/` 폴더 또는 옛 `docs/기능맵.md`)이 없으면 `/stop-loop:setup` 을 먼저 돌리라고 알리고 멈춘다.

## 조사 순서

근거가 강한 것부터 본다.

1. 확정된 시나리오(`docs/plan/SC-*.md`)의 요소
2. 완료 카드와 그 커밋 — `git log --grep='Loop-Issue: <카드>'` 로 카드별로 바뀐 파일을 얻는다
3. 진입점(API 경로·화면·명령·배치 작업)과 시험 파일
4. 문서와 색인 밖 파일은 `rg` 로 찾고, 없으면 `grep`. `graft` 가 있으면 `graft map`·`graft skeleton`·
   `graft callers` 로 관계를 뽑되 후보로만 쓴다 — 확인하지 않은 후보는 줄에 쓰지 않는다.

## 줄 쓰기

`${CLAUDE_PLUGIN_ROOT}/setup/기능맵.md` 의 칸 규칙을 따른다.

- 기능 하나의 크기는 틀 그대로다 — 입력과 출력이 있고 밖에서 관찰되는 동작 하나. 화면·API·배치 작업 하나 수준.
- 기존 줄은 고치지 않고 덧붙이기만 한다. 줄은 그 기능이 속한 그룹 파일(`docs/기능맵/<그룹>.md`)에 덧붙인다.
  맞는 그룹 파일이 없으면 그룹 이름을 사람에게 제안해 확인받은 뒤 새 파일(제목 한 줄과 표 머리 두 줄)을 만든다.
  옛 `docs/기능맵.md` 만 있는 프로젝트에서는 그 파일에 덧붙인다.
  ID 는 옛 파일과 모든 그룹 파일을 통틀어 마지막 번호 다음부터 쓴다.
- 줄을 쓰기 전에 기존 맵의 기능 이름과 코드 위치를 먼저 읽는다. 같은 기능이 이미 있으면 건너뛴다
  (같은 진입점·같은 코드 위치). 겹치는 범위로 다시 불러도 같은 기능이 두 번 들어가지 않게 한다.
- 코드 위치는 실재하는 파일만 적는다. 시험을 못 찾으면 `—`.
- 짝 관계(같은 기능의 다른 구현)는 추측하지 않고 사람에게 묻는다.
- 소스 파일에 머리 주석을 달지 않는다.

더할 기능이 없으면(전부 이미 있어 건너뛴 경우 포함) 「더할 줄 없음」을 알리고 맵을 건드리지 않는다.

## 끝내기

1. `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/featuremap_check.py" .` 를 돌려 통과(종료 코드 0)를 확인한다.
   어긋나면(1) 어긋난 줄을 사람에게 알린다.
2. 더한 줄 목록과 사람이 확인할 것을 알린다 — 정의가 맞는지, 짝 관계.
3. 커밋하지 않는다. 검토와 커밋은 사람이 한다.
