# 기능맵

이 프로젝트의 기능 목록이다. 기능은 이 폴더(`docs/기능맵/`)의 그룹 파일에 적는다 — 파일 하나가 기능 그룹(업무 영역) 하나다
(예 `회원.md`·`정산.md`). 표 한 줄이 기능 하나 — 입력과 출력이 있고 밖에서 관찰되는 동작 하나다.
기능 ID(`F-ddd`)는 그룹과 무관하게 프로젝트 전체에서 하나다. 그룹을 옮겨도 번호는 그대로이고, 기능 하나는 한 파일에만 둔다.
01 분석과 05 설계는 입력에 실린 자리를 소스를 검색하기 전에 `rg -n "<ID>"` 로 조회하고, 카드 머리말 `기능:` 의 ID 와
그 「관련 기능」에서 영향 범위를 잡는다.

정본 규칙: 구현된 기능의 정본은 코드와 이 기능맵이고, 계획 중인 기능의 정본은 시나리오(`docs/plan/SC-*.md`)다.

## 칸 쓰는 법

- **ID** — `F-` 와 세 자리 숫자(예 `F-012`). 한 번 붙이면 바꾸지 않는다. 폐기해도 줄을 지우지 않고 상태만 바꾼다.
- **정의** — 한두 줄. 무엇을 받아 무엇을 내는가.
- **상태** — `계획` · `구현됨` · `폐기` 셋 중 하나.
- **코드 위치** · **시험 위치** — 경로(필요하면 `경로:함수`). 모르면 `—`.
- **근거 문서** — 계획 중인 기능은 시나리오 경로와 요소 번호만 적는다(예 `docs/plan/SC-02.md E-3`).
  시나리오 문장을 옮기지 않는다 — 옮기면 두 곳이 어긋난다.
- **관련 기능** — `종류:ID` 를 쉼표와 빈칸으로 잇는다(예 `짝:F-013, 앞:F-001`). 종류는 다섯 가지다.
  `앞`(먼저 도는 기능) · `뒤`(이어서 도는 기능) · `짝`(같은 기능의 다른 구현 — 원본과 이식본) ·
  `같은명세`(같은 명세를 따르는 기능) · `대체`(실패하면 대신 도는 기능). 다른 그룹 파일의 ID 를 가리켜도 된다.
- **알려진 문제** — 없으면 `—`.

빈 칸은 `—` 로 적는다.

예시(표의 자료가 아니라 모양만 보이는 것):

```
| F-012 | 로그인 요청을 받아 토큰을 낸다 | 구현됨 | src/auth.py:login | test_auth.py | — | 짝:F-013 | — |
```

## 그룹 파일 머리

그룹 파일은 제목 한 줄과 표 머리 두 줄로 시작한다. 그룹 파일을 만들 때 이 모양을 그대로 쓴다.
